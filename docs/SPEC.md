# 引用系統樹 PoC 仕様書（SPEC.md）

- ステータス: ドラフト（PoC フェーズ）
- 対象分野: 計算機科学（OpenAlex Field ID 17）
- 最終更新: 2026-11-09

---

## 1. 目的

研究論文の「引用関係」を、生物の系統樹のように時間とともに広がる構造として可視化する。
研究者が、分野・論文・著者の範囲から出発して、被引用の多い重要論文（ハブ）に素早くたどり着けるようにする。

### 1.1 ゴール（PoC）
- 計算機科学の、限られた範囲の引用ネットワークを系統樹で表示できる。
- ハブ（分岐の多い論文）を大きく・濃い色で強調し、被引用の上位へ数クリックで到達できる。
- 文字を常時表示せず、ホバーで論文名を確認できる。
- 1つのシード論文から、その系譜（祖先）と子孫を辿れる。

### 1.2 非ゴール（PoC では扱わない）
- 人文系など他分野の対応（次フェーズ）。
- 全件（約 24.9 億件の引用関係）の保持。
- 論文の本文検索、PDF の表示、ユーザー認証、共有機能。
- 商用利用（外部 API とデータのライセンス確認が前提）。

## 2. 用語

| 用語 | 定義 |
|---|---|
| シード | 探索の起点となる論文 |
| 祖先 | シードが引用している論文（系統樹の根側、古い方） |
| 子孫 | シードを引用している論文（系統樹の枝先側、新しい方） |
| 分岐数 | 論文を直接引用している、取り込み済みの論文の数（直接の子の数） |
| ハブ | 分岐数が「ハブの基準」以上の論文。基準は UI で変更可能（既定 4） |
| 系譜 | 選択した論文から起点までの祖先の列 |
| 骨格 | すべてのハブとその祖先だけからなる部分木 |
| 分野 DB | 分野ごとに分けた D1 データベース（例: `field_17_computer_science`） |

## 3. 全体アーキテクチャ

```
[オフライン処理（PC/VM）]
  OpenAlex スナップショット（CC0）
      │  分野17の論文・引用エッジを抽出・整形
      ▼
  分野DB（D1）＋ 事前構築済みグラフ（R2）

[Cloudflare（Workers Paid）]
  Worker（API）
   ├─ Cache API   … 同一リクエストの短期キャッシュ（拠点単位）
   ├─ R2          … シード単位のグラフ JSON（長期キャッシュ）
   ├─ D1          … 論文・引用エッジ・分野内索引
   ├─ Durable Objects … 外部 API 呼び出しの直列化（レート制御）
   └─ Queues / Cron   … 深さ2以上の展開・定期更新（PoC では任意）

[フロントエンド]
  単一 HTML（SVG 描画、バニラ JS）
   └─ /api からグラフを取得して描画（PoC のプロトタイプは架空データ）
```

### 3.1 各コンポーネントの役割
- **Worker**: API の提供、キャッシュ確認、必要時のみ外部 API 呼び出し。
- **D1（分野ごと）**: 論文の基本情報と引用エッジ。分野・年・著者・被引用数で絞り込む。
- **R2**: シード単位の完成済みグラフ（年・分岐数・被引用数を含む JSON）。読み出し負荷の低減が目的。
- **Cache API**: 同じ API 応答の短期再利用。拠点ごとに保持されるため、永続化の役割は持たせない。
- **Durable Objects**: Semantic Scholar のレート制限（初期値 1 リクエスト/秒）に合わせて、外部呼び出しを 1 本の列に並べる。

### 3.2 やらないこと
- Worker のメモリ（128 MB）に全グラフを載せない。
- Worker 上で全件の ETL（抽出・変換・読み込み）を行わない。ETL はオフラインで行う。

## 4. データ仕様

### 4.1 データソース
| ソース | 用途 | 注意 |
|---|---|---|
| OpenAlex | 論文・分野・被引用の基本データ（主データ源） | 2026-02-13 以降 API キーが必要（無料）。`cites` フィルタで被引用、`referenced_works` で参考文献を取得。一覧取得は 1 ページ最大 100 件、ページ番号方式は先頭 1 万件まで（以降はカーソル方式） |
| Semantic Scholar | 引用の意図（intent）、影響力のある引用の判定（補助） | キーなしは共有プール。キーありで初期値 1 RPS。利用条件を確認すること |

ライセンス:
- OpenAlex のデータは CC0 で、再利用・再配布は可能。
- Semantic Scholar の利用条件（商用可否など）は実装前に必ず確認する。

### 4.2 分野
- PoC の分野は計算機科学（OpenAlex Field ID **17**）。
- 分類階層: Domain → Field → Subfield → Topic（26 Field / 252 Subfield / 4,516 Topic を確認済み）。
- 人文系は Field ID **12**（Arts and Humanities）。次フェーズで扱う。
- 分野 DB は分野ごとに分けるが、スキーマは共通で `papers.field` 列を持つ（4.4 の結合ルール参照）。

### 4.3 PoC の取り込み範囲（案）
- 分野 17、発表年 **直近 10 年**（2016〜2026）。
- 各論文の被引用数の上位 N 件とその引用エッジ（N は DB 容量を見て決める）。
- 取り込み対象外の論文は、祖先としてのみ必要な場合に限り追加する。

### 4.4 D1 スキーマ（案）

```sql
-- 論文
CREATE TABLE papers (
  id        INTEGER PRIMARY KEY,   -- OpenAlex の W 番号（数値部分）。分野をまたいで一意
  field     INTEGER NOT NULL,      -- OpenAlex Field ID（計算機科学は 17、人文系は 12）
  title     TEXT NOT NULL,
  year      REAL NOT NULL,         -- year + (month-1)/12 の小数値（例: 2016年6月 → 2016.417）。OpenAlex `publication_date` 由来。系統樹の X 軸を月単位の精度で配置するため（2026-11-09 変更。マイグレーション 0002）
  cit       INTEGER NOT NULL,      -- 被引用数（OpenAlex 値）
  fwci      REAL,                  -- Field-weighted Citation Impact（OpenAlex `fwci`。出版年+3年分の被引用数/期待値の比。確認済み）
  subfield  INTEGER,
  child_cnt INTEGER NOT NULL DEFAULT 0,  -- 取り込み済みの直接の子（分岐数）
  doi       TEXT                  -- OpenAlex `doi`（"https://doi.org/..." 形式）。外部リンク用（マイグレーション 0003、2026-11-10）
);
CREATE INDEX idx_papers_field_year ON papers(field, year);
CREATE INDEX idx_papers_field_cit  ON papers(field, cit DESC);

-- 引用エッジ（cited = 祖先、citing = 子孫）
CREATE TABLE edges (
  cited   INTEGER NOT NULL,
  citing  INTEGER NOT NULL,
  PRIMARY KEY (cited, citing)
) WITHOUT ROWID;
CREATE INDEX idx_edges_citing ON edges(citing);

-- 著者（論文名検索と合わせて著者名でも検索できるようにするため正規化。マイグレーション 0004、2026-11-10）
-- 1論文に複数行（複数著者）を持つ。S3 からの ingest 実装時に実データを投入する想定（このテーブル定義のみ先行追加）。
CREATE TABLE authorships (
  paper_id    INTEGER NOT NULL,
  author_name TEXT NOT NULL
);
CREATE INDEX idx_authorships_paper ON authorships(paper_id);
CREATE INDEX idx_authorships_name  ON authorships(author_name);

-- キーワード（OpenAlex `keywords`: STRUCT(id, display_name, score)[] を辞書化。マイグレーション 0005、2026-11-10）
-- OpenAlex の語彙は分野をまたいで有限（約数万語）なため、辞書テーブルは分野 DB をまたいで重複しても小さい。
CREATE TABLE keywords (
  id   TEXT PRIMARY KEY,  -- OpenAlex の keyword スラッグ（例: "mysql"）
  name TEXT NOT NULL      -- OpenAlex の display_name（例: "MySQL"）
);

-- 論文とキーワードの中間テーブル（多対多）。1論文に複数行、1キーワードも複数論文に紐づく。
CREATE TABLE paper_keywords (
  paper_id   INTEGER NOT NULL,
  keyword_id TEXT NOT NULL,
  score      REAL,  -- OpenAlex の score（関連度、0.0〜1.0）
  PRIMARY KEY (paper_id, keyword_id)
) WITHOUT ROWID;
CREATE INDEX idx_paper_keywords_keyword ON paper_keywords(keyword_id);
```

- 分岐数は `child_cnt` として事前計算する（集計クエリを毎回走らせない）。
- ID は数値に変換して容量を抑える。
- 1 データベースの上限は 10 GB。分野 DB は必要に応じて、年代・サブ分野で分割する。

#### 分野 DB の結合ルール（後で一緒に扱うため）
- すべての分野 DB は**同一スキーマ**とし、`papers.field` 列を必ず持たせる。
- `papers.id` は OpenAlex の ID そのもの（分野をまたいで一意）なので、結合しても衝突しない。
- 結合は `UNION ALL` で行い、分野の絞り込みは `field` 列で行う。
- **分野をまたぐ引用エッジ**（例: 計算機科学の論文が人文系の論文を引用）は、**引用する側（citing）の分野 DB** に保存する。
  - 結合後に祖先が別の分野 DB にあっても、`edges` と `papers` を両方結合すれば辿れる。
  - 祖先の論文情報が自分の分野 DB に無い場合は、祖先の行を `papers` に複製する（`field` は祖先の分野の値を入れる）。
- `child_cnt` は分野内の数を保存する。分野をまたいだ分岐数は、結合後に再計算する。

### 4.5 R2 のグラフ JSON（案）

キー: `graph/field{分野ID}/seed-{id}-d{depth}.json`（例: `graph/field17/seed-123456-d2.json`。2026-11-10、`worker/graph.ts` の `graphKey()`）

```json
{
  "seed": 123456,
  "field": 17,
  "generatedAt": "2026-11-09T00:00:00Z",
  "nodes": [
    { "id": 123, "y": 2019, "t": "論文名", "c": 85, "k": 4 }
  ],
  "edges": [[123, 456]]
}
```
- `y`: 出版年月（`year + (month-1)/12` の小数値。例: 2016.417 = 2016年6月）、`t`: 論文名、`c`: 被引用数、`k`: 分岐数。
- `edges` は `[祖先ID, 子孫ID]` の配列。

## 5. API 仕様（案）

すべて `GET`、JSON 応答。`:field` は分野 ID（計算機科学は 17）。分野・年代ごとに D1 を分割する方針
（4.4「分野 DB の結合ルール」、ARCHITECT.md 3.4.2）に対応し、`:field` パスパラメータと `yearRange`
クエリパラメータ（`"2016-2026"` 形式、省略時はその分野の既定レンジ）でどの DB を見るか指定する
（`worker/db.ts` の `DB_REGISTRY` が実際に登録済みの組み合わせの正とする。2026-11-10 追加）。

| パス | 説明 | 主なパラメータ |
|---|---|---|
| `/api/fields` | 登録済みの分野・年代レンジの一覧（フロントの切り替え UI 用） | — |
| `/api/fields/:field/top` | 被引用の上位論文 | `from`（年）、`limit`（既定 50、最大 200）、`yearRange` |
| `/api/fields/:field/hubs` | 分岐数の上位論文 | `minChild`（既定 4）、`limit`、`yearRange` |
| `/api/fields/:field/seed/{id}` | シード周辺のグラフ | `depth`（既定 2、最大 3）、`minCit`、`yearRange` |
| `/api/fields/:field/search` | 論文名・著者名の検索（`papers` と `authorships` を LEFT JOIN、どちらかに部分一致でヒット。2026-11-10 著者名検索を追加） | `q`、`limit`、`yearRange` |
| `/api/fields/:field/paper/{id}` | 論文の詳細と系譜 | `yearRange` |

応答の共通事項:
- キャッシュ可能なものには `Cache-Control` を付ける。
- 取得できなかった場合は、`404`（論文なし、または `:field`/`yearRange` に対応する DB が未登録）、`400`（パラメータ不正）、`429`（外部 API 制限）、`503`（一時的な失敗）を返す。

### 5.1 キャッシュ方針（案。数値は実測で調整）

| 対象 | 保存先 | 有効期間 |
|---|---|---|
| 上位・ハブの一覧 | Cache API | 1 時間 |
| シードのグラフ | R2 | 7 日（再取得はキュー経由） |
| 論文の基本情報 | D1 | 更新時に上書き |
| 外部 API の応答 | R2（生データ） | 30 日 |

キャッシュキー例:
- `graph:f17:seed:{id}:d{depth}`
- `top:f17:from{year}:l{limit}`

## 6. フロントエンド仕様

### 6.1 画面構成
- **ヘッダー**: タイトル、注意書き（サンプル表示時）、凡例（ハブ・非ハブ）。
- **操作バー**: 被引用の上位（表示件数）、骨格のみ、全体表示。年スライダーは実装したが UI として分かりにくいとの判断で撤去した（2026-11-09）。「最多被引用へ」ボタンは、円の大きさで被引用上位が判別できるため撤去した（2026-11-10）。被引用1位の論文へは、サイドパネルの「被引用の上位」一覧から到達できる。「ハブの基準」の調整 UI も撤去した（2026-11-10）。円の色・大きさは分岐数の連続値で決まり基準の影響を受けないため、基準を変えても見た目が変わらず分かりにくかった。ハブ判定は既定値 4 に固定（6.2 参照）。
- **メイン（左）**: 系統樹 SVG。ドラッグで移動、ホイールで拡大縮小。
- **サイドパネル（右）**: 選択中の論文（詳細・系譜・操作）、被引用の上位 10 件、ハブ上位 10 件。

### 6.2 系統樹の描画ルール
- 左から右へ時間が進む（X 軸 = 出版年）。
- 枝は親（祖先）から子（子孫）へ伸びる Bezier 曲線。
- 行の並び（Y 軸）は、子の被引用合計の多い順に上から配置する（系統の並びを安定させるため）。
- **円のサイズ**: 分岐数に応じて大きくする（ハブほど大きい）。分岐 0 の論文は小さい点。実データでは分岐数の分布が大きく偏るため（2026-11-09 実測: 平均14、最大7735）、対数スケールを採用し、巨大ハブが画面を占有しないようにする（当初案の平方根スケールから変更）。
- **円の色**: 分岐 0 は灰色、分岐がある論文は琥珀色から赤へ（分岐の多さに比例）。
- **ハブ**: 分岐数 ≥ 4（固定値、`src/filters.ts` の `HUB_MIN_CHILD_DEFAULT`）。ハブかどうかは骨格のみ表示の絞り込みと、ホバー時のツールチップ表示に使う。当初は操作バーで基準を変更できたが、変更しても円の色・大きさ（分岐数の連続値で決まる）には反映されず分かりにくかったため、固定値に戻した（2026-11-10）。
- **ラベル**: 常時表示しない。ホバーでツールチップ（論文名、出版年、被引用数、分岐数、ハブ表示）。
- **アニメーション**: 表示・非表示の切り替えに限る（フェードと拡大）。再生機能は持たない。

### 6.3 表示の絞り込みルール
表示対象は次の条件をすべて満たす論文とする。
1. 被引用の上位 N 件、またはその祖先（N = 表示件数）。骨格のみが ON のときは、ハブとその祖先、および選択中の系譜。
2. 「この系統に集中」中は、フォーカス論文の祖先と子孫。
3. 祖先が折りたたまれていない。

### 6.4 操作
| 操作 | 結果 |
|---|---|
| 円をクリック | 論文を選択。系譜を強調し、他を薄く表示。祖先の折りたたみを解除。 |
| 一覧の項目をクリック | 同上（被引用 1 位の論文へは「被引用の上位」一覧の先頭から到達できる） |
| 子を折りたたむ / 展開 | 子孫の表示を切り替え |
| この系統に集中 | フォーカスを設定し、表示件数を全件にする |
| 選択解除 | 選択を解除 |
| 全体表示 | フォーカス解除、表示位置をリセット |
| 骨格のみ | ハブと祖先だけ表示 |

### 6.5 性能目標（PoC）
- 表示ノード 600 件（架空データ）で、表示件数の変更がおおむね 100 ms 以内に反映される。
- 実データでは、描画ノード数を 2,000 件程度までに抑える（超える場合は表示件数で制限）。

### 6.6 非対応（PoC）
- モバイルでの細かい操作（最低限の表示のみ）。
- キーボード操作、スクリーンリーダー対応（次フェーズで検討）。

## 7. 非機能要件

- **コスト**: Workers Paid の範囲で運用できること。R2 の保存料金は少額で収まる見込み。
- **再現性**: 取り込みの元データ（OpenAlex のスナップショット日付）を記録する。
- **帰属表示**: 利用データの出典（OpenAlex、Semantic Scholar）を画面に表示する。
- **個人情報**: 論文データのみを扱う。利用者の検索履歴は保存しない（PoC）。
- **障害時**: 外部 API が失敗した場合は、キャッシュ済みの結果を返し、最新でないことを示す。

## 8. 制約とリスク

| 項目 | 内容 | 対応 |
|---|---|---|
| D1 の容量 | 1 DB 10 GB | 分野・年代で DB を分割 |
| Worker のメモリ | 128 MB | グラフは R2 から必要分だけ読む |
| 外部 API の制限 | OpenAlex は日次の上限あり。Semantic Scholar は 1 RPS（キーあり） | 事前構築、Durable Objects で直列化 |
| データの網羅性 | 引用数は OpenAlex 独自の値（他の DB と異なる） | 出典を明記 |
| 分野の差 | 人文系は引用数が少ない（平均約 1.8、神経科学は約 21.2） | 分野内の正規化指標を併記 |
| 見た目の過密 | ノードが多いと線が絡む | 表示件数・骨格・ハブ基準で絞る |
| 数値の確認 | OpenAlex のフィルタ名・上限値は実装前に公式で確認。`fwci`（Field-weighted Citation Impact）は確認済み（2026-11-09）。`publication_year:年-年` のハイフン範囲構文は実測では動作するが公式ドキュメントに明記がないため、`from_publication_date`/`to_publication_date` を正式採用 | 残りの数値（APIキーの日次予算等）は検証項目に含める |
